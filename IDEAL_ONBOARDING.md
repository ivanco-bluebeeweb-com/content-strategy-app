# Content Strategy Hub — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md` §9 (приложения без классического
`connect_*` к внешнему сервису). Целевой пользователь: контент-стратег/SEO-менеджер,
планирующий редакционный календарь и контент-опорную стратегию для сайта.

## 1. "Credential type" — его нет напрямую
Нет `connect_*`. Первое действие — `create_site_profile` (зарегистрировать управляемый
сайт). Реальную ценность даёт связка с внешними данными (Google Search Console через
отдельный коннектор, WordPress Hub) — это hub, синтезирующий чужие данные.

## 2. Идеальный флоу
1. **Первое открытие** — `Empty` с прямым CTA "Зарегистрировать сайт" — форма профиля
   сайта (домен, бренд, языки, бизнес-описание) сразу в центре.
2. **Cross-app data dependency emphasis** — идеально: ЧЕСТНО показать, что часть
   функций (`discover_opportunities_from_search_console`) требует ОТДЕЛЬНО подключённого
   Google Search Console Connector — явный баннер "подключите Search Console, чтобы
   получать реальные поисковые запросы для контент-идей", а не молчаливая пустота при
   вызове функции без данных.
3. **Обязательный порядок** — `run_content_audit` явно помечен как MANDATORY перед
   генерацией новой стратегии — идеально: этот шаг должен быть первым логичным CTA
   после регистрации сайта, не спрятан среди прочих равнозначных кнопок.
4. **После аудита** — редакционный календарь/очередь опций — сразу видно, что делать
   дальше (какие статьи писать, в каком порядке).
5. **Multi-site** — список сайтов с быстрым переключением, как у WordPress Hub.
